# JWT and JWKS Script Manual

This document explains how to run `generate_jwt_and_jwks.sh`, what it generates, and its behavior.

## Script

- Script file: `generate_jwt_and_jwks.sh`
- Purpose: generate an RSA key pair (if needed), create a signed JWT (RS256), and generate a JWKS file.

## Prerequisites

- Bash shell
- OpenSSL
- xxd (usually available with Vim/common Unix tooling)

## Usage

```bash
./generate_jwt_and_jwks.sh <issuer> <subject> <audience> [key_dir]
```

### Arguments

- `issuer`: value used in JWT `iss` claim
- `subject`: value used in JWT `sub` claim
- `audience`: value used in JWT `aud` claim
- `key_dir` (optional): directory where keys and outputs are stored
  - default: `./keys`

If fewer than 3 arguments are provided, the script exits with code `1` and shows:

```text
Uso: ./generate_jwt_and_jwks.sh <issuer> <subject> <audience> [key_dir]
```

## Recommended Claim Mapping (for your authentication flow)

For the token generated by this script, use:

- `issuer` = `client_id`
- `subject` = `client_id`
- `audience` = URL of the signed authentication request endpoint
- `iat` = current Unix timestamp at token generation time
- `exp` = `iat + TTL_SECONDS`
- `jti` = unique token identifier generated for each token

The audience can be, for example:

- `<domain>/v1/bc-authorize`
- `<domain>/v1/token`

## Environment Variables (optional)

These variables are optional and can be set before running the script:

- `KID`: key id used in JWT header and JWKS key entry
  - default: derived from the public key fingerprint, so the same key pair keeps the same `kid`
  - override it by exporting `KID` before running the script
- `TTL_SECONDS`: token lifetime in seconds
  - default: `300`
  - required: must be between `1` and `300`

If `TTL_SECONDS` is not an integer, is `<= 0`, or is `> 300`, the script exits with error.

This matches the requirement that the Authorization Server rejects requests when `exp` is more than 300 seconds later than its receipt time.

Example:

```bash
KID=my-key TTL_SECONDS=300 ./generate_jwt_and_jwks.sh <issuer> <subject> <audience>
```

## Output Files

By default (or inside `key_dir` if provided), the script creates/uses:

- `private.pem`: RSA private key
- `public.pem`: RSA public key
- `token.jwt`: signed JWT
- `jwks.json`: JWKS document with the public key (`kty`, `use`, `alg`, `kid`, `n`, `e`)

## Behavior Details

### First run (no keys in target directory)

- Generates a new RSA private key (`private.pem`)
- Extracts the public key (`public.pem`)
- Generates a new signed token (`token.jwt`)
- Generates JWKS (`jwks.json`)

### When keys already exist

- If `private.pem` already exists, the script reuses it (does not rotate keys)
- If `public.pem` is missing, it is extracted again from the existing private key
- The `kid` is derived from the public key, so the same key pair always keeps the same `kid`
- A new token is always generated (new `iat`/`exp`), and `token.jwt` is updated
- Each new token has a new unique `jti` value
- `jwks.json` is regenerated to match the active key and `KID`

In short: existing private/public keys are kept, and only the token is refreshed on each run.

## Example Commands

```bash
./generate_jwt_and_jwks.sh my-client-id my-client-id https://example.com/v1/bc-authorize
```

```bash
./generate_jwt_and_jwks.sh my-client-id my-client-id https://example.com/v1/token ./keys
```
